## daily-puzzle-system.md

- **[Bug] Result-card countdown rolls over at midnight instead of offering today's puzzle** (`index.html` `openModal`, lines 623-632). `isToday` is evaluated once when the card opens. If the card stays open past 00:00 IST in a visible tab, the tick recomputes `todayIST(appNow() + 86400000)`, so "Next paheli in" silently restarts at about 24h (counting to the *following* midnight) and `#playToday` stays hidden, although today's puzzle is already out. Technical Plan §4 says the countdown counts "to 00:00 IST", and CUJ 4 / item 15 say a stale date hides the countdown and shows "Play today's paheli". This is only re-evaluated on `solve()`/reopen or via the `visibilitychange` toast, not by the countdown itself.
- **[Bug] A decodable but malformed puzzle record leaves the app stuck on "Loading…" with no `puzzle-error`** (`index.html` `boot`, lines 341-353). Only `fetch`/`json()`/`readPuzzleFile` sit inside the `try`; `readPuzzleFile` (`lib/codec.js`) checks only `schema`, so a record with a missing or bad `grid`/`clues` throws from `buildPuzzle`, `gridHash` or `entries[0].cells` outside the `try`. That is an unhandled rejection with no error screen. The §2 screens table says "any other failure" shows "Something went wrong. Refresh the page." and sends `puzzle-error`. (Risk is lowered because `check.yml` validates published files.)
- **[Drift] `publish.mjs` holds back every approved puzzle when any one fails the re-check** (`tools/publish.mjs` lines 137-141). The approved records are checked together, and any error marks *all* of them "refused: checker failed", with nothing written. §5 step 6 says "Approval is per puzzle, so good ones are never held back", and item 9 says publish reports per-date published/skipped/refused.
- **[Drift] `storage-unavailable` is sent only when today's puzzle loads successfully** (`index.html` line 347). On the pre-launch, running-late, offline and error screens the event is never sent. §3 says "Umami gets `storage-unavailable` once per page load".
- **[Drift] Manual checklist does not cover all CUJs 1-9** (`tests/manual-checklist.md`). Item 18 requires checks for each CUJ. Missing: CUJ 4 (finishing across midnight, "Play today's paheli"), CUJ 5 (device clock in another time zone, for example London 19:00 = 00:30 IST), CUJ 6's "Copy" address button and the `report-clue` event, CUJ 7 (batch approval flow), and the §2 midnight behaviour in an open tab ("A new paheli is out" toast vs auto-reload of an unstarted puzzle).
- **[Drift] `load` was not renamed to `loadPuzzle`** (`index.html`). Item 15 says to "Rename the local `load` to `loadPuzzle`". The loader is now `boot()` and no `loadPuzzle` exists. (`save` → `persist` was done.)
- **[Drift] "Saved on this browser" sits outside the screenshot area** (`index.html` line 209). `#storageNote` comes after the closing tag of `#shareCard`. §4 lists it inside "Result card (the screenshot area)" with time, help line and streaks.
- **[Drift] Batch-mode "already published" skip is keyed on puzzle files, not the manifest** (`tools/check.mjs` lines 111, 117, 186). `checkBatch` treats a date as published if a `puzzles/<date>.json` file exists (`loadPublished(...).entries`). Item 7 says to skip records "whose date is already in the manifest". `publish.mjs` and `make-sheet.mjs` do use the manifest, so an orphan file (or a manifest date with a missing file) makes the three tools disagree.
- **[Drift] Offline screen wording differs from spec** (`index.html` lines 325, 340). The title is "You're offline" and the body is "Check your connection and try again." §2 specifies "You're offline. Check your connection." + Retry, and CUJ 9 says "You're offline. Check your connection and tap Retry."
- **[Drift] Pause screen differs from spec** (`index.html` line 512). The eyebrow changes to "Chai break" and the body reads "Paused at m:ss. The grid is hidden, so no peeking." §4 says the start-screen body reads "Paused at m:ss" with "Resume" and keeps the eyebrow "Paheli Mini #N". (The reload-resume path in `showStart` does match.)
- **[Doc-only] Undocumented `reason` property on `puzzle-error`** (`index.html` line 365). This sends the first 60 characters of the error message. §4 lists only `puzzle` and `v` for that event.
- **[Doc-only] `puzzle-solve` sends `streak: null` when storage is unavailable** (`index.html` line 598). The design does not define the value in that case.
- **[Doc-only] Prototype footer replaced, not removed** (`index.html` line 196). The new footer reads "A new paheli every day at midnight IST. Streaks are saved on this browser." §4 lists "the prototype footer" under Removed and specifies no replacement.
- **[Doc-only] Midnight handler also reloads non-puzzle screens** (`index.html` line 517). When `P` is null (pre-launch, running late, offline or error) and the India date changed, the tab reloads on becoming visible. §2 covers only unstarted/started/solved puzzles.
- **[Doc-only] Umami tag carries `data-domains="arvind13496.github.io"`** (`index.html` line 7). This is not in the design. It means no events are recorded from `localhost`, so Umami checks only work on the live site (the checklist puts them under "Live site only").
- **[Doc-only] utm cleanup order differs from item 15's boot sequence** (`index.html` `sendPageview`, lines 272-283). Item 15 step 3 removes `utm_*` before fetching. The code removes it asynchronously, after the Umami pageview is sent (possibly after boot finishes). This follows §4's "only then" rule, so the two parts of the doc conflict.
- **[Doc-only] Undocumented checker rule** (`tools/check.mjs` line 43). A clue keyed to a slot id that does not exist in the grid is an error. This is not listed in §5 step 2.
- **[Doc-only] Published mode skips the GK `source` rule** (`tools/check.mjs` line 57, `published` flag). §5 / item 7 say published mode runs "the shape, content and answer-leak rules". `source` is stripped before scrambling, so this rule can't apply, but the doc does not say so.
- **[Doc-only] Review sheet layout differs in detail** (`tools/make-sheet.mjs` lines 17, 45-57). The Tag column shows "Riddle"/"GK"/"Pop" instead of R/GK/N. The grid uses "■" for blocks with letters space-separated. Warnings and Self-solve are merged per puzzle on its first row, while §5 step 4 lists them as per-clue-row columns.
- **[Doc-only] `clearProgress` signature** (`lib/state.js` line 65). It is `clearProgress(date)` and clears only when `progress.date === date`. Item 4 lists `clearProgress()` with no argument, although §3's ownership rule needs the date.
- **[Doc-only] Check tests use different examples than item 10** (`tests/check.test.mjs` lines 121-131). The answer-in-clue case uses RAO in "Kiran rao directed this", not "TEA" in "Spill the tea". The whole-word case uses SON inside "sooner", not "ATE" inside "later". The rules tested are the same.
- **[Doc-only] Item 13 `package.json` bullet is malformed in the doc** (design lines 750-755). `"engines"` is listed between `"test"` and the other three scripts, as if `check`/`sheet`/`publish` were nested under `engines`. The real `package.json` is correct.
